# Atropos — Hypothesis-Killing Library — Deployment Methodology

A portable document: how to deploy the hypothesis-killing method in any project that works with hypotheses and data. The document is self-contained — an analyst or an AI agent with zero context deploys everything from scratch using it alone. Project-specific values are marked with placeholders: `[PROJECT_ROOT]`, `[DATA_DIR]`, etc.

The core of the method: every hypothesis runs a 7-stage pipeline with kill criteria fixed in advance. Possible outcomes: `KILLED` (dead — to the graveyard), `SURVIVED` (alive — may back a decision), `INCONCLUSIVE` (not enough data — reopen on a new snapshot).

---

## 1. Prerequisites

The minimal data infrastructure required:

- **A data catalog** `[DATA_DIR]` with versionable snapshots: the data state is frozen on `[SNAPSHOT_DATE]` and never modified afterward.
- **A reproducible source** `[DATA_SOURCE]` (DB, files, API): the query or export is saved as text next to the snapshot.
- **A data dictionary**: fields, units of measurement, coverage period. Without it, kill criteria are unmeasurable.
- **A git repository** `[PROJECT_ROOT]`: all hypothesis artifacts are committed; history is append-only.
- **Python 3.11+** with the ability to create virtual environments.

Nothing beyond this is required: the method does not depend on a DB stack, a cloud, or paid tools.

## 2. Directory Structure

Create in `[PROJECT_ROOT]` (in the Atropos project the layout is generated by
`atropos init` — files are generated, never overwritten):

```text
[PROJECT_ROOT]/
├── docs/
│   └── HYPOTHESIS_KILLING_FRAMEWORK.md   # the main methodology document
├── hypotheses/
│   ├── preregistrations/                  # H-NNNN: preregistrations (before data)
│   ├── code/                              # H-NNNN: test code
│   ├── graveyard/                         # H-NNNN: tombstones (verdicts)
│   └── INDEX.csv                          # registry of all hypotheses
├── data/                                  # [DATA_DIR]
│   ├── snapshots/                         # snapshots: snapshots/[SNAPSHOT_DATE]/
│   └── DATA_DICTIONARY.md                 # data dictionary
├── tests/                                 # pytest tests for hypothesis code
├── scripts/                               # linters and registry utilities
├── pyproject.toml                         # dependencies (uv), ruff/mypy/pytest config
└── AGENTS.md, CLAUDE.md                   # agent instructions (templates included)
```

The key rule: one hypothesis = one `H-NNNN` identifier = at least three artifacts: prereg, code, tombstone.

## 3. Python Environment

The package manager is **uv** (fast, reproducible, lock file committed):

```bash
cd [PROJECT_ROOT]
uv python pin 3.12                # pin the interpreter version
uv init --package                 # creates pyproject.toml with the package skeleton
uv add numpy pandas scipy         # runtime dependencies
uv add --dev pytest ruff mypy     # dev tools
uv sync                           # create .venv and install everything per uv.lock
```

Every command below runs through `uv run` (e.g. `uv run pytest`); activating the environment is not needed.

The minimal stack: `numpy` (computation), `pandas` (data), `scipy` (statistics), `pytest` (tests), `ruff` (style: 78 columns, docstrings, perflint, E741 — configured in `pyproject.toml`), `mypy` (types: strict mode). Extend only as needed; versions are pinned in `uv.lock` automatically.

## 4. Step-by-Step Deployment

| Step | Action | Result |
|------|--------|--------|
| 1 | Create the directory structure (section 2) | Empty skeleton committed to git |
| 2 | Set up the Python environment (section 3) | `pyproject.toml` + `uv.lock` committed |
| 3 | Freeze the first data snapshot and the dictionary | `[DATA_DIR]/snapshots/[SNAPSHOT_DATE]/` ready |
| 4 | Write `docs/HYPOTHESIS_KILLING_FRAMEWORK.md` | 7 stages, 6 laws, the prereg and tombstone formats |
| 5 | Fill in `AGENTS.md` and `CLAUDE.md` (replace the placeholders) | Agent instructions with no `[PLACEHOLDER]` left |
| 6 | Run a pilot hypothesis `H-0001` through the full cycle | A tombstone in the graveyard + a row in INDEX.csv |
| 7 | Commit everything, appoint an owner `[OWNER]` | The method is live |

The `H-0001` pilot is chosen to be clearly killable: the point of the step is to test the graveyard mechanics, not to produce a surviving hypothesis.

## 5. CI/CD Integration

Mandatory checks on every pull request — portable to any CI (GitHub Actions, GitLab CI, Jenkins, etc.):

1. `uv run ruff check .` and `uv run ruff format --check .` — code style (78 columns, docstrings, perflint, E741), zero warnings.
2. `uv run mypy` — strict typing, zero errors.
3. `uv run pytest -q` — unit tests; hypothesis code without a test does not pass CI.
4. The preregistration linter `scripts/lint_preregistrations.py` (about 20 lines of Python): every `preregistrations/H-*.md` must contain an ID, a falsifiable prediction, a numeric kill criterion, a snapshot, a seed, an author, a date.
5. A cross-check of `hypotheses/INDEX.csv` against the graveyard directory: every hypothesis with a tombstone has a registry row.

GitHub Actions example (abridged):

```yaml
- run: uv run ruff check .
- run: uv run ruff format --check .
- run: uv run mypy
- run: uv run pytest -q
- run: python scripts/lint_preregistrations.py
```

Optional: a nightly job that recomputes all `SURVIVED` hypotheses on a fresh data snapshot — a check that the survivors have not died on new data.

## 6. Onboarding

The onboarding protocol (30-60 minutes), in order:

1. Read `docs/HYPOTHESIS_KILLING_FRAMEWORK.md` — the pipeline and the laws.
2. Read `AGENTS.md`; Claude-compatible agents also read `CLAUDE.md`.
3. Read 3-5 random tombstones from `graveyard/` — how kill criteria and verdicts are phrased.
4. Skim `INDEX.csv` — which classes of hypotheses are already closed.
5. Pilot: take a training hypothesis (prefix `H-TRAIN-*`) to its tombstone under a mentor's supervision.

Readiness criterion: the newcomer produces a linter-passing preregistration on their own, without hints.

## 7. Scaling

- **10 hypotheses.** Flat files and manual upkeep of `INDEX.csv`. The `H-NNNN` naming discipline is enough.
- **100 hypotheses.** A graveyard check before every new hypothesis is mandatory — search by tags, not by titles; `[TAGS]` are mandatory in a preregistration; a WIP cap of no more than `[WIP_LIMIT]` open hypotheses per analyst.
- **1000 hypotheses.** Automation: scripted registry search, tag clustering, batches (one test script = a family of related hypotheses), a periodic "KILLED/SURVIVED share by class" report. The main threat is duplication, so every new hypothesis class is first searched for in the graveyard.

The scaling rule: as the number of hypotheses grows, the cost of a graveyard check must fall (through automation), not rise.

## 8. Common Pitfalls

| Pitfall | Symptom | Remedy |
|---------|---------|--------|
| Post-hoc criterion drift | The kill criterion gets "refined" after a look at the data | Commit the prereg before the data pull; the linter; law 5 |
| Resurrecting a killed hypothesis | The same hypothesis under a new name | A graveyard check by tags and structure, not by title |
| Unpinned seed | The test is not reproducible | Seed is a mandatory preregistration field (law 3) |
| Snapshot drift | The test computes on a different snapshot than declared | Snapshot ID in both the prereg and the test code |
| Verdict inflation | Only other people's hypotheses make it to the graveyard | CI cross-check of INDEX.csv against preregistrations/ |
| Skipping the graveyard "from memory" | Duplicates pile up | The graveyard check is a pipeline stage, not a habit |
| A pilot on real data | Garbage in the registry | The `H-TRAIN-*` prefix and a separate directory |

## 9. Definition of Done

- [ ] The directory structure from section 2 exists and is committed.
- [ ] `pytest`, `ruff` and `mypy` pass locally and in CI.
- [ ] The preregistration linter works and catches empty kill criteria.
- [ ] The pilot `H-0001` has gone through the full cycle and rests in the graveyard.
- [ ] `AGENTS.md` and `CLAUDE.md` are filled in — not a single `[PLACEHOLDER]` left.
- [ ] A new analyst passes onboarding (section 6) without outside help.

## Appendix A. Preregistration Template

```markdown
# H-[NNNN]: [TITLE]
- Author: [AUTHOR], date: [DATE], tags: [TAGS]
- Prediction: [MEASURABLE_FALSIFIABLE_PREDICTION]
- Kill criteria: [METRIC] < [THRESHOLD] on snapshot [SNAPSHOT_DATE], seed [SEED]
- Graveyard check: [WHAT_WAS_SEARCHED], result: [FOUND_NOTHING | DUPLICATE_OF_H-XXXX]
```

## Appendix B. Tombstone Template

```markdown
# H-[NNNN] — [KILLED | SURVIVED | INCONCLUSIVE]
- Verdict: [VERDICT], date: [DATE], author: [AUTHOR]
- Metric: [ACTUAL_VALUE] vs threshold [THRESHOLD] (snapshot [SNAPSHOT_DATE])
- Cause: [ROOT_CAUSE]; lesson: [LESSON]; do not retry: [DO_NOT_RETRY]
```
