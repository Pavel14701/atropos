# TEMPLATES.md — 5 шаблонов Atropos (системы убийства гипотез)

Пять копируемых шаблонов: прereg до данных, диагностический скрин
без гейтов, батарея робастности, post-mortem после смерти, бриф
субагенту. Каждый шаблон = скелет с плейсхолдерами `<...>` —
заполняется ДО касания данных теми числами, которые туда просятся.
Правило жизни: ноль параметров после данных, ноль календарей,
ноль «может быть пригодится».

> Примеры в блоках «Заполнение из примера» цитируют пререги и логи
> закрытого корпуса-донора — этих файлов нет ни в поставке, ни в вашем
> workspace. Раскладку workspace (`hypotheses/`, graveyard, реестр)
> scaffold with `atropos init` (files are generated, never
> overwritten).

## Шаблон 1. PREREG — пре-декларация до первой точки данных

Фиксирует гипотезу, конструкцию, нули и критерии убийства ДО сбора
данных; коммит файла = неизменяемый хеш протокола. Золотой стандарт —
семь гэпов OFI-пререга: каденс, executable-экономика, latency,
направленность, pooling, de-clustering, гейты.

```text
# PREREG: <имя гипотезы> (v1.0)

Дата: ГГГГ-ММ-ДД. Статус: заморожено ДО первой точки данных.
Коммит этого файла = хеш протокола. Любая правка = новая версия,
старый тест аннулируется. Forward-only.

## 1. Гипотеза (1 строка)
<Фактор X предсказывает Y на горизонте L. Не Z, не W —
<уточнение таргета одной строкой>.>

## 2. Замороженная конструкция (параметры / пороги / нормализация)
- Каденс: L_primary = <...>; L_secondary = {...} — только robustness,
  НЕ могут воскресить.
- Forward return НЕПЕРЕКРЫВАЮЩИЙСЯ (иначе HAC/Newey-West, лаг >= L).
- Нормализация: <например, z-score по rolling std, окно = N баров —
  число зафиксировано>.
- Экономика: executable (half-spread entry+exit + fees), НЕ mid.
  «<X> bp на mid — не <X> bp, которые заберёшь».
- Latency-гейт: half-life > 2 × (poll interval + order RTT),
  не 2 × one-way; <ts_recv − ts_exchange> и <order_ack − order_send>
  логируются отдельно.
- Направленность: <порог входа, one-sided/two-sided — до данных>.
  Abs-вариант — только в лог, не в kill.
- Pooling: pooled с instrument fixed effects ИЛИ per-instrument +
  агрегация знака — зафиксировано ОДНО до сбора.
- De-clustering: события с шагом >= L; «200 событий подряд в одном
  окне = 1 событие»; N_min считается по НЕзависимым событиям.
- Power (записано расчётом, не произволом): N = <...> даёт t ~ 2 при
  <эффект>; N_min = <...>.
- Data quality: исключать <пропуски уровней / stale > Xs / нулевой
  объём>.

## 3. Нулевые контролы (3-6, каждый с порогом)
| #  | Контроль                                        | Порог                  |
|----|-------------------------------------------------|------------------------|
| N1 | Placebo: 200 перемешанных <меток/дней> (seed)   | p < 0.05               |
| N2 | Инкрементал над контролами <список>             | t > 2 И ΔR² >= <порог> |
| N3 | Знак стабилен по <terciles/годам> (pre-defined) | <порог>                |
| N4 | <повторные измерения / второй актив / издержки> | <порог>                |

## 4. Критерии убийства (дословно, пре-декларированы)
KILL: <t < 2 incremental> ИЛИ <placebo p > 0.05> ИЛИ <экономика <
порог> на executable>.
Провал любого = семья закрыта. Никаких «но если посмотреть под
другим углом».

## 5. Immutable hash
Коммит этого файла = хеш ДО первой точки данных. Правка после =
новая версия, старый тест аннулируется. Без этого подгонка
неизбежна.

## 6. Честный прогноз
Априорная вероятность прохода: <X>%. Что скорее всего убьёт:
<конкретный гейт с цифрой>. Убийство по правильной причине —
успех, не провал.

## 7. Очередь после коммита
СТОП: <сколько данных/времени копится>. Параллельные семьи <те,
что дают коррелированные чтения> НЕ запускать. Их прereg можно
подготовить по этому же шаблону, не коммитя.

## ЗАПРЕЩЕНО
- КАЛЕНДАРНЫЕ ТЕРМЫ: <«2022 медвежий -> +15», годовые режимы,
  сезонные окна> — это подгонка известной истории; OOS она не
  переносится (см. могилу GLM-spot: пилот +0.53 -> OOS +0.053).
- Менять пороги/окна/нормализацию после первой точки данных.
- Второй прогон после неудачи первого = новый прereg, не правка.
```

**Заполнение из примера:** `PREREG_OFI_SHADOW_2026-11-02.md` — золотой
стандарт (§1-§7 = семь гэпов; kill: «t < 2 incremental ИЛИ
placebo p > 0.05»; §12 честный прогноз: «гейт 1 скорее убьёт на
5-25 bp вместо 40 — но по правильной причине»). Forward-гейт
вариант: `PREREG_BAB_TIER2_2026-11-01.md` (52 недели, K-F/K-D/K-DIR,
«провал любого — судьба S5»). Порт + capacity вариант:
`PREREG_PORT_VARIANT_C_2026-11-02.md` (рамка $50-70k ревизована
recount'ом вниз до $20-30k — честная самопроверка до запуска).

## Шаблон 2. DIAGNOSTIC SCREEN — разведка без гейтов

Скрин данных без гейтов и без вердиктов: кандидат либо умирает
здесь наглядно, либо уходит в dated prereg. Чистейший kill —
XS-reversion: отрицательный EV в почти всех годах при t −3.19.

```text
# ДИАГНОСТИЧЕСКИЙ СКРИН: <имя> — NO GATES, NO VERDICT
Статус: DIAGNOSTIC ONLY. Вердиктов этот прогон не даёт; исход —
«могила», «премис-смерть» или «dated prereg». Никаких грейлов.

## 1. Раскрытия (house-находки, релевантные гипотезе)
(a) <сестра/кузен уже закрыт: что именно, числа, путь к логу —
    почему этот тест НЕ переупаковка (corr порог)>;
(b) <survivorship: панель живущих листингов — лонг-чтения
    ограничены сверху, шорт не видит худших>;
(c) turnover kill-line: > 20 RT/yr/символ = авто-смерть;
(d) <известный негативный приор на семейство — почему всё равно
    проверяем (инкрементал, а не грааль-флип)>.

## 2. Данные: пути + ограничения
- Панель: <data/...>, n = <...> символов (исключены: <кто, почему>),
  сетка <ГГГГ-ММ-ДД .. ГГГГ-ММ-DD> (<N> дней).
- Короткие окна: <файл, покрытие> — SHORT WINDOW DISCLOSED LOUDLY.

## 3. Премис-чек: условие вообще существует?
<Разброс фактора по кросс-секции: p10/p50/p90; частота события;
доля живых дней>. Если условия нет — DEAD на премисе, дальше не идём.

## 4. Сигнальный тест: сырой эффект + t + по годам
- Конвенция книги: <ранги, издержки, timing без look-ahead>.
- Итог: n=<...>  EV <...>%  t <...>  hit <...>%
- По годам:
    <2019: <...>% (n=...)>
    <2020: <...>% (n=...)>
    <...>
  Знак-консистентность: <k/N> лет.
- По активам: позитивных <k/N>.

## 5. Инкрементальный тест: регрессия с контролами
Коэффициент фактора ПОСЛЕ контролов <список известных факторов>;
t инкрементала = <...>. t < 2 = эффект есть эхо известного фактора.

## 6. Нулевые распределения (200 прогонов, seed зафиксирован)
- Shuffle/permutation/placebo: <что перемешивается, что остаётся>.
- Реал = <...> процентиль своей плацебо-выборки (<k>/200 прогонов
  match-or-beat).

## 7. Честный исход: как выглядит смерть (репорт verbatim)
Если мёртв — репортим дословно: «<фактор> не предсказывает:
EV <...>% t <...>, отрицателен в <k/N> лет, позитивен у <k/N>
активов — могила». Никаких «но при другом окне жив».
DIAGNOSTIC ONLY -- no gates, no verdict.
```

**Заполнение из примера:** `runs/xs_reversion_screen.log` — чистейший
kill: «XS-REVERSION alt/BTC: n=2553 ev −0.442% t −3.19 hit 60%»,
по годам отрицателен 7/8 (единственный плюс 2025: +0.052%),
активов позитивных 1/9, финальная строка «DIAGNOSTIC ONLY — no
gates, no verdict». Раскрытия и данные как в живом брифе:
`runs/round11_academic_screens.log` (HOUSE DISCLOSURES a-e),
премис-чек и shuffle-200 на каждый фактор/арму:
`runs/round12_xs_academic.log`.

## Шаблон 3. ROBUSTNESS BATTERY — 7 тестов с порогами

Диагностика чувствительности на уже найденном эффекте: эффект,
живущий в одной точке параметров или в одном периоде, — артефакт.
Гейтов нет; вердикт собирается из измеренных чисел, не из нарратива.

```text
# БАТАРЕЯ РОБАСТНОСТИ: <кандидат> — 7 тестов, пороги фиксированы
Статус: ROBUSTNESS — no gates. Sensitivity probes only; пиннед-
кандидат остаётся исходной спецификацией.
Якорь [0]: воспроизведение исходного сплита бит-в-бит ДО тестов
(реал t = <...> совпал с источником).

## [1] THRESHOLD SENSITIVITY: порог {0.5x, 1x, 1.5x, 2x} базового
  <Эффект + 95% CI при каждом пороге>.
  Правило: смена эффекта > 2x при сдвиге порога = DEAD (эффект
  живёт в щели одного параметра — overfit).

## [2] WINDOW SENSITIVITY: окно {0.5x, 1x, 2x} базового
  <Жив ли эффект на соседних окнах? Жив только на базовом окне =
  подгонка окна>.

## [3] SUBPERIOD THIRDS: трети выборки (или годы)
  <Эффект + CI в каждой трети>. Жив (знак + CI) во ВСЕХ трёх =
  ROBUST. Жив в одной трети = режим-артефакт.

## [4] LEAVE-ONE-OUT: дроп по одному символу/активу
  <Эффект + CI после каждого дропа>. Эффект не должен держаться
  на одном символе: дроп «носителя» убивает = не эффект рынка.

## [5] PLACEBO NULL: 200 прогонов (seed зафиксирован)
  <Что разрушается (выравнивание сигнал x исход), что остаётся
  (сами исходы)>. Реал обязан сесть выше 95-го процентиля своей
  плацебо-выборки. Ниже 95-го = DEAD, что бы ни показывали t.

## [6] DE-CLUSTERING: дроп топ-1% наблюдений
  <Эффект + CI без топ-1% (экстремальные дни/сделки)>. Плюс:
  кластеризация по датам/месяцам — naive t завышен, cluster-SE
  обязателен.

## [7] SIGN STABILITY: монотонная лестница квантилей
  <q1 < q2 < q3 < q4> (или строгое убывание). Зигзаг = эффект несёт
  только крайний бакет = шум.

## ВЕРДИКТ-СБОРКА (измеренные числа, без нарратива)
  [1] <порог: значения x4, жив? True/False>
  [2] <окна: значения x3, жив? True/False>
  [3] <трети: 3/3 или k/3>
  [4] <LOO: k/k>
  [5] <placebo: percentile <...> (порог > 95)>
  [6] <топ-1%: пережил? cluster-t <...> vs naive t <...>>
  [7] <лестница: q1..q4, монотонна? True/False>
  FINAL: ROBUST | NOT ROBUST — <перечисление True/False>.
```

**Заполнение из примера:** `runs/poc_robustness.log` — подлинный
проход: секции [0]-[9], placebo percentile **0.0** в обоих нулях
(unrestricted и symmetric-side) = genuine, трети 3/3 с CI, LOO 4/4,
лестница near < mid < far монотонна → «FINAL: ROBUST». Подлинный
фейл: `runs/exkurt_walkforward.log` — in-sample спред −0.024
(t −4.54) сжался в walk-forward до −0.0046 (t −0.57) = **~5x
shrink = overfit**, лестница q1..q4 немонотонна, 2 kill-правила
сработали → GRAVEYARD.

## Шаблон 4. POST-MORTEM — 5 диагностик после смерти

Вскрытие умершей семьи: отвечает «почему выглядело живым», не
«как воскресить». Никаких гейтов, кандидатов и воскрешений — семья
остаётся закрытой; причина смерти фиксируется одной строкой.

```text
POST-MORTEM: <семья> -- diagnostics only (post-hoc, declared)
NO gates, NO candidates, NO resurrection. Семья остаётся CLOSED.
inputs: <файл данных> x <запечатанный исход>, n=<...>

== [0] БАЗОВОЕ ВОСПРОИЗВЕДЕНИЕ (замороженная рубрика, n=<...>) ==
  <Метрики file vs re-run; инкрементальный t ПОСЛЕ контролов
  <список> — место, где умерло. Naive i.i.d. SE рядом для сравнения.>

== [1] PLACEBO: 200 перемешанных прогонов (seed, declared post-hoc) ==
  <Реал vs своё плацебо-распределение: mean/sd, p2.5/p97.5>.
  Реал сидит на percentile <...>; <k>/200 прогонов match-or-beat.
  Проверка масштаба: i.i.d. sigma vs placebo sd (ratio <...>).

== [2] КВАНТИЛЬНАЯ ЛЕСТНИЦА (бакеты по скору, n по бакетам) ==
  <EV + CI по каждому бакету>.
  Монотонность (ранг vs EV): Spearman <...>, Kendall <...>.
  Spread top-Q1 = <...>; средняя треть плоская? (да/нет)

== [3] ЯЧЕЙКИ РЕЖИМОВ: какая ячейка несёт эффект? ==
  <Дельта hi-score vs lo-score внутри тертилей <фактора>;
  пустые ячейки помечены. Дельта живёт в одной ячейке с малым n =
  артефакт ячейки, не эффект>. Плюс объявленные post-hoc
  конъюнкции — явно помечены как post-hoc.

== [4] DE-CLUSTERING ==
  <Дроп топ-k |fwd| наблюдений из топ-бакета: эффект пережил?>
  Кластеризация по месяцам: naive t <...> -> cluster t <...>.

== [5] АТРИБУЦИЯ: что общего у топ-дециля? Что убило лоу-дециль? ==
  <Состав топ-дециля по режимам/годам; сработавшие термы
  top/rest; worst-3 с числами>.
  <Сравнение rising/falling months — в какие месяцы эффект
  разворачивается и каким известным фактором это объясняется.>

POST-MORTEM end -- диагностика завершена; семья остаётся CLOSED.
Причина смерти (одна строка): <например: «сырой эффект настоящ
(percentile 100), но инкрементал мёртв (t +0.73 после контролов)
= эхо MVRV-моментума»>.
```

**Заполнение из примера:** `runs/glm_v2_postmortem.log` — все пять
диагностик на GLM v2: placebo percentile **100** (сырой Spearman
+0.215 настоящ), лестница монотонна (Spearman +1.00), режим-ячейки
(mvrv HIGH несёт дельту +36.2 при n=3 в лоу-бакете), de-clustering
(месячная кластеризация режет t 3.09 -> 2.38), атрибуция
(top-decile = calm IV x MVRV>75; лонги в falling months дают
−12.2%). Смерть — инкрементал: t +0.73 после контролов
iv/rv/mvrv/skew = **MVRV-momentum echo**; «family remains CLOSED».

## Шаблон 5. AGENT BRIEFING — бриф субагенту (7 обязательных блоков)

Стандартный заголовок задачи для субагента марафона: без этих семи
блоков агент либо изобретает свои нули, либо приносит негейтованный
нарратив. Смерть — валидный результат брифа, не провал агента.

```text
# БРИФ АГЕНТА: <имя задачи> (v<н>)

## БЛОК 1. ENVIRONMENT
- Репо: <абсолютный путь>. Python: <версия/окружение>.
- Инструмент записи: <Write/лог>; лог результата: runs/<имя>.log.
- cwd между вызовами сбрасывается — только абсолютные пути.

## БЛОК 2. CONTEXT + DISCLOSURES (house-находки, релевантные задаче)
(a) <что уже закрыто рядом: семья/сестра, числа, путь к логу>;
(b) <признанные оговорки: survivorship, funding-покрытие,
    концентрация периода — обязательны в любом чтении>;
(c) <пересечения с параллельными агентами: SIBLINGS IN PARALLEL —
    смежное тестируют sibling-агенты, здесь REPORT-ONLY>.

## БЛОК 3. DATA
- Точные пути: <data/...>; схема: <колонки, каденс, сетка дат>;
  критерий включения: <например, >= 913 daily bars>.
- Ограничения: <короткие окна ГРОМКО: файл, покрытие, даты>;
  <издержки/фандинг с какой даты>.

## БЛОК 4. TASK (нумерованные шаги с измеримыми выходами)
1. <Построить X> -> выход: <таблица/число в логе>.
2. <Проверить Y> -> выход: <число>.
3. <Свести вердикт-сборку> -> выход: <секция SUMMARY>.
Каждый шаг кончается измеримым артефактом (числом в логе),
не словом «изучить».

## БЛОК 5. NULLS
- Ревьюер (вербатим): <дословная формулировка нуля от reviewer>.
- House-обязательные: shuffle/placebo 200 прогонов в КАЖДОЙ
  фактор/арме; per-year таблицы обязательны; кластер-SE
  (даты/месяцы) рядом с naive.

## БЛОК 6. KILL (критерии пре-декларированы, с порогами)
- (a) turnover kill-line: > 20 RT/yr/символ = авто-смерть;
- (b) <статистический порог: t < 2 / CI содержит 0 / percentile
  < 95> = семья закрыта;
- Kill-line решает сама; обход или пересмотр kill-line после
  данных = нарушение протокола.

## БЛОК 7. EXPECTED HONEST OUTCOME (как выглядит смерть — verbatim)
- Если мёртв, репортим дословно: «<фактор>: EV <...>% t <...>,
  негативен в <k/N> лет, позитивен у <k/N> активов — могила».
- Смерть = валидный результат (могила пополняется), спасение
  другим окном/порогом после данных = провал брифа, не успеха.
```

**Заполнение из примера:** `runs/round11_academic_screens.log` —
реальный заголовок брифа марафона: origin = external review,
HOUSE DISCLOSURES (a)-(e) с числами (стаблкоин-урок, kill-line 20
RT/yr) и DATA с «SHORT WINDOW DISCLOSED LOUDLY» (123.5d).
`runs/round12_xs_academic.log` — второй живой образец: binding
discipline (a)-(e) (kill-line решает; shuffle/placebo 200 в каждой
фактор/арме; per-year таблицы обязательны) + строка «SIBLINGS IN
PARALLEL: ... overlaps here are REPORT-ONLY».

## Как шаблоны стыкуются

Скрин (шаблон 2) без гейтов находит маргинальный эффект -> прereg
(шаблон 1) замораживает проверку до данных -> батарея (шаблон 3)
проверяет, не щель ли это в одном параметре -> смерть вскрывается
post-mortem'ом (шаблон 4) -> следующий агент получает вывод через
бриф (шаблон 5). Ни один шаблон не выдаёт «грааль» — только
верdict из измеренных чисел: могила или dated prereg.
