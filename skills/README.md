# SKILLS — исполняемые протоколы пайплайна убийства гипотез Atropos

> Индекс папки. Родительские документы: `../FRAMEWORK.md` (философия,
> pipeline 7 этапов, 6 законов, таксономия 18 терминов смерти),
> `../TEMPLATES.md` (5 шаблонов), `../CASES_AND_FLAGS.md` (8 флагов,
> 5 case studies, чек-лист агента). Каждый skill самодостаточен: агенту
> нужен только файл + данные; все числа взяты из
> `docs/THEORY_GRAVEYARD.md` и `runs/*.log` репозитория
> deterministic-trading-engine.

## Порядок использования (usage order)

**Skill 1 → 2 → 3 → 4 → 5 → 6.** Порядок фиксирован: каждый этап дешевле
следующего, гипотеза умирает на самом раннем сработавшем kill-критерии
(`../FRAMEWORK.md` §2, §5 — красная нить). Пропускать этапы запрещено.

1. **Skill 1 первым:** могильник + премис + данные + инструмент + cost-линия
   — смерть здесь стоит 1-3 query.
2. **Skills 2-4 вместе на старте скрина** (урок волны-3): nulls (2) и
   инкременталь (4) — обязательный СТАРТ, сырой сигнал (3) даёт честную
   картину и мощность. Инкременталь — решающий тест: «красивые сырые
   числа ничего не значат, если инкременталь их убивает».
3. **Skill 5** после инкрементального прохода: 7 тестов, ≥5/7 + нет
   системного паттерна в фейлах.
4. **Skill 6 последним:** walk-forward на замороженных порогах + годовые
   дамми + репликация на свежих днях.

## Правила для любого субагента

- Один прогон по замороженному протоколу, один вердикт: **graveyard или
  датированный прereg** — третьего исхода нет.
- Смерть = валидный результат брифа, не провал агента; каждую смерть
  записать в могильник с причиной (один первичный термин таксономии),
  ключевыми числами и условиями воскрешения.
- Ноль параметров после данных. Ноль календарей в скоринге.
  Ноль «может быть пригодится».
- Шаблоны для оформления прогонов — `../TEMPLATES.md`: скрин (шаблон 2),
  прereg (шаблон 1), батарея (шаблон 3), post-mortem (шаблон 4),
  бриф субагенту (шаблон 5).
